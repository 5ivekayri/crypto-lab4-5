# Мини-шпаргалка — LAB5

**Что сделал:** вычисление и сравнение хешей строк и файлов; выбор MD5, SHA-1,
SHA-256, SHA-384, SHA-512; сравнение скорости на файле 16 МиБ.

| Вопрос | Ответ для защиты |
| --- | --- |
| Что такое хеш-функция? | Преобразует данные произвольной длины в результат фиксированной длины. |
| Хеширование — шифрование? | Нет: у обычного хеша нет ключа расшифрования и обратной операции. |
| Что такое коллизия? | Разные входные данные дают один и тот же хеш. |
| Совпадение хешей доказывает равенство? | Не строго: коллизии возможны. Разные хеши точно означают разные входные байты для одного алгоритма. |
| Где используется? | Проверка целостности, сравнение данных, электронная подпись. |
| Какой тип принимает ComputeHash? | Массив байтов или поток. Возвращает массив байтов. |
| Как хешируется строка? | UTF-8 → байты → ComputeHash → HEX. |
| Зачем UTF-8 вместо ASCII? | ASCII теряет кириллицу; разные символы могут превратиться в одинаковые `?`. |
| Как хешируется файл? | FileStream → ComputeHash; без чтения всего файла в память. |
| HEX — шифрование? | Нет: текстовая запись байтов, по два символа на байт. |
| Длины MD5 / SHA1 / SHA256 / SHA384 / SHA512? | 128 / 160 / 256 / 384 / 512 бит. |
| Сколько HEX-символов у SHA256? | 256 / 4 = 64. У MD5 — 32. |
| Что сломано в цикле методички? | `Length - 1` пропускает последний байт; MD5 получается 30 символов вместо 32. |
| Как сравниваются хеши? | По длине и всем байтам, а не по ссылкам на массивы. |
| Почему хеш строки и файла может отличаться? | В файле могут быть BOM или завершающий перевод строки. |
| Какие алгоритмы устарели? | MD5 и SHA-1 не обладают нужной стойкостью к коллизиям. |
| Можно хранить пароль как MD5? | Для хранения паролей нужны специальные схемы с salt и затратным вычислением, а не обычный быстрый MD5. |
| Чем измерял время? | Stopwatch: прогрев и семь измерений, итог — медиана. |
| Что входит в замер? | Открытие, чтение файла и хеширование; вывод и HEX не входят. |
| Что получилось быстрее? | В сохранённом запуске SHA-1: 10.705 мс на 16 МиБ; SHA-256: 11.326 мс. |
| Можно ли обобщить рейтинг? | Нет: он зависит от процессора, реализации, кеша и нагрузки. |

Показ преподавателю из папки `LAB5`:

```sh
dotnet run -- text MD5 "MySourceData"
dotnet run -- compare-text SHA256 "abc" "abc"
dotnet run -- compare-text SHA256 "abc" "abd"
dotnet run -- file SHA256 examples/input.txt
dotnet run -c Release -- demo
dotnet run -c Release -- self-test
```

**Короткий вывод:** «Добавил файловое хеширование и выбор пяти алгоритмов.
Проверил сравнение хешей и исправил потерю последнего байта в методичке.
Замерил скорость на одинаковом файле. Хеширование позволяет проверять целостность,
но не скрывает данные; скорость алгоритма не определяет его стойкость».
