## Методичка и демонстрация

Из исходных фрагментов воспроизведён цикл с `Length - 1`:

```text
MD5("MySourceData"), ошибка: 8FD2486D263C1EE4FCF7FA70742F23
MD5("MySourceData"), верно:  8FD2486D263C1EE4FCF7FA70742F2397
MD5("NotMySourceData"):     F7711A634146F20AB86D1E5A8F870CE3
```

ASCII-кодирование «А» и «Б» даёт одинаковые байты; UTF-8 сохраняет различие,
и проверенные SHA-256 отличаются. Опечатки `sSourceData` и `D5CryptoServiceProvider`
выявлены при чтении исходных фрагментов; отдельная сборка этих неполных фрагментов
не выполнялась.

В [examples/report.md](examples/report.md) сохранены хеши исходного файла,
сравнения с его копией и изменённым файлом: для всех алгоритмов копия совпала,
изменённый файл — нет.

## Измерение скорости

Сохранённый запуск `demo`: 16 МиБ одинаковых данных, по одному прогреву и семь
замеров на алгоритм. Все числа и контрольные хеши находятся в
[examples/benchmark.md](examples/benchmark.md).

| Алгоритм | Медиана, мс | Скорость, МиБ/с |
| --- | ---: | ---: |
| MD5 | 23.082 | 693.17 |
| SHA1 | 10.705 | 1494.59 |
| SHA256 | 11.326 | 1412.64 |
| SHA384 | 22.641 | 706.69 |
| SHA512 | 22.881 | 699.29 |

В этом запуске SHA-1 оказался самым быстрым; это наблюдение для данной машины
и условий измерения, а не рекомендация выбирать SHA-1 для защиты данных.
Результат включает чтение из файловой системы после прогрева и может отражать
работу кеша ОС.
