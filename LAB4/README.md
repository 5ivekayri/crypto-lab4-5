# Лабораторная работа № 4 — AES

Выполнены задания из методички: изучен алгоритм AES, проверен исходный листинг,
реализованы файловый ввод/вывод и эксперимент со сменой ключа через смену пароля.
Программа на C# использует AES-256-CBC и стандартную библиотеку .NET 10.

## Запуск

Из корня репозитория:

```sh
cd LAB4
dotnet build -c Release
dotnet run -- self-test
dotnet run -- demo
```

`demo` создаёт отдельную папку `results/<дата-время>`: исходный файл, шифротексты
для паролей A и B, восстановленные файлы, повторное шифрование с A и `report.txt`.
Можно задать свою новую или пустую папку: `dotnet run -- demo results/my-demo`.
Готовый пример выполнения сохранён в [examples](examples).

Работа со своим текстовым файлом UTF-8:

```sh
dotnet run -- encrypt samples/input.txt encrypted.txt
dotnet run -- decrypt encrypted.txt decrypted.txt
```

Каждая команда запрашивает пароль. При вводе в терминале он не отображается.
Для расшифрования используй тот же пароль. Существующий выходной файл программа
не перезаписывает: укажи новое имя. Пути с пробелами заключай в кавычки.
Пароль можно передать через стандартный ввод для автоматических проверок.

Программа рассчитана на текстовые файлы UTF-8, помещающиеся в память.
Содержимое текста и переводы строк сохраняются; BOM при чтении удаляется,
выход записывается как UTF-8 без BOM. Произвольные бинарные файлы не поддерживаются.

## Что изменено в листинге

| В методичке | В рабочем решении |
| --- | --- |
| `RijndaelManaged`, блок 256 бит | `Aes.Create()`, блок 128 бит |
| Ключ 256 бит | Ключ 256 бит, то есть AES-256 |
| IV 32 байта | IV 16 байт |
| PBKDF2 с неявным SHA-1, 1000 итераций | Явный PBKDF2-SHA256, 210000 итераций |
| Устаревший `RNGCryptoServiceProvider` | `RandomNumberGenerator.GetBytes` |
| Один вызов `CryptoStream.Read` | `DecryptCbc` возвращает весь расшифрованный массив |
| Ввод/вывод текста в консоли | Чтение и запись файлов |

Число итераций PBKDF2 выбрано как параметр учебной реализации. При изменении этого
значения старые файлы нельзя расшифровать без возврата прежнего параметра.

Размер блока и размер ключа — разные параметры. В современных .NET исходная строка
`BlockSize = 256` вызывает `PlatformNotSupportedException`. Исходные классы извлечены
из методички без изменения в [Reference](Reference). Их можно запустить отдельно:

```sh
dotnet run --project Reference/Original.csproj
```

После ввода пароля и текста на .NET 10 ожидается ошибка о размере блока.
Это воспроизведение ошибки исходника; основной проект собирается отдельно.
Исходный листинг также выдаёт предупреждения об устаревших API.
Результаты фактических запусков приведены в [VALIDATION.md](VALIDATION.md).

Документация Microsoft:
[размер блока Rijndael](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rijndaelmanaged.blocksize),
[установка .NET SDK](https://learn.microsoft.com/en-us/dotnet/core/install/linux-scripted-manual).

## Как устроено шифрование

1. Текст преобразуется в байты UTF-8.
2. Генерируются случайные salt (32 байта) и IV (16 байт).
3. PBKDF2-SHA256 получает 32-байтовый ключ из пароля и salt.
4. AES-256-CBC шифрует текст с дополнением PKCS7.
5. В файл записывается `Base64(salt || IV || ciphertext)`.

При расшифровании из Base64 извлекаются salt, IV и шифротекст. Из введённого пароля
и сохранённого salt получается тот же ключ; AES восстанавливает байты, затем UTF-8 — текст.
Пароль и ключ в зашифрованном файле не хранятся. Salt и IV не являются секретами.
Формат отличается от формата исходного примера; старые файлы с ним несовместимы.

## Эксперимент со сменой ключа

В демонстрации используются публичные учебные пароли `Lab4-password-A` и
`Lab4-password-B`. Шифрование с A и расшифрование с A восстанавливает текст;
аналогично B → B. Попытка A → B приводит к ошибке либо неверным данным.
Проверяется также повторное шифрование с A: шифротекст меняется из-за новых salt и IV.
Поэтому различие шифротекстов само по себе не доказывает смену пароля.

Длина ключа остаётся 256 бит: изменяется его значение. Даже при одинаковом пароле
новый salt порождает другой ключ. Длину ключа нельзя менять через `BlockSize`.

Сохранён CBC из методички: этот учебный формат не содержит MAC и не проверяет
подлинность данных. Ошибка padding/UTF-8 может обнаружить неверный пароль или
повреждение, но не гарантирует обнаружение любой подмены. Для прикладной защиты
потребовался бы формат с проверкой подлинности, например AES-GCM.

## Проверки и вывод

`self-test` проверяет пустой текст, границы блока, кириллицу, emoji, большой текст,
случайность salt/IV, смену пароля, неверный формат, файловый цикл и запрет перезаписи.
Есть независимый контрольный пример: ключ получен через Python `hashlib.pbkdf2_hmac`,
шифротекст — через `openssl enc -aes-256-cbc`. Его параметры: salt = байты 0..31,
IV = байты 0..15, пароль `fixture-password`, текст `Независимый пример AES 🔑\n`,
PBKDF2-SHA256 с 210000 итерациями. Фиксированные salt/IV используются только в тесте.

Вывод: AES позволяет зашифровать содержимое файла и полностью восстановить текст
с правильным ключом. Смена пароля меняет производный ключ; правильное восстановление
требует того же пароля, salt и параметров алгоритма.

Краткие ответы для защиты: [CHEATSHEET.md](CHEATSHEET.md).
